# 테스트 레벨 — 정의와 설정

이 플러그인이 다루는 테스트 레벨의 **정의**와, 프로젝트가 어느 레벨을 쓸지 고르는 **설정 파일 형식·판정 규칙**의 단일 출처.
`work` 와 세 스킬(`unit-test` / `integration-test` / `e2e-test`)은 판정 규칙을 자기 본문에 복사하지 않고 이 파일을 참조한다.

## 1. 레벨 정의 — 플러그인 고정

**레벨이 무엇인지는 플러그인이 정하고, 프로젝트는 "어느 레벨을 쓸지"만 고른다.**
정의를 프로젝트 코드베이스 스캔에 맡기면 폴더 하나로 정책이 뒤집힌다.

| 값 | 한국어 | 대상 | 환경 | 담당 스킬 |
|---|---|---|---|---|
| `unit` | 단위 테스트 | 한 모듈 안 — ViewModel / UseCase / Repository 구현 / Mapper / 순수 함수 | JVM (Android) · XCTest (iOS) | `unit-test` |
| `integration` | 경계 테스트 | 모듈 경계를 넘는 데이터·계약 — 매핑 / 직렬화 / 에러 전파 | JVM · XCTest | `integration-test` |
| `ui` | UI 테스트 | Composable 렌더링 / 화면 조작 / 기기 플로우 | 기기 · Robolectric · 시뮬레이터 | `e2e-test` |
| `none` | (테스트 없음) | — | — | 없음 |

값 이름을 `integration` 으로 둔 것은 기존 `integration-test` 스킬·`TESTING.md` 용어와 끊기지 않게 하기 위해서다. 본문에서는 "경계 테스트(integration)"로 병기한다.

**UI 모듈의 경계**: `:feature` / `:presentation` 모듈에서 `unit` 의 대상은 **ViewModel 과 그 아래까지**다. Composable 렌더링은 `ui` 다. MVI 구조라면 ViewModel 의 상태 전이·이벤트 방출을 단언하는 것으로 화면 로직 대부분이 덮인다.

**`integration` 과 `ui` 의 경계**: 판단 기준은 **"Robolectric 없이 JVM 단독으로 도는가"** 이지 "DB 를 쓰는가"가 아니다. DB 테스트가 Robolectric 을 요구하면 그것은 `ui` 다.

> ⚠️ **Robolectric 은 여기서 `ui` 다.** Android 실무에서는 Robolectric 을 JVM unit 테스트로 분류하는 팀이 많지만, 이 플러그인은 그렇게 보지 않는다. `@RunWith(RobolectricTestRunner::class)` 가 붙은 ViewModel 테스트도 `ui` 레벨이다 — 기준이 "무엇을 테스트하나"가 아니라 "**Android 프레임워크 없이 도는가**"이기 때문이다. 이 정의를 바꾸려면 이 파일을 고쳐야 하며, 프로젝트 설정으로는 못 바꾼다.

레벨 **정의**만 플러그인이 갖는다. 도구·실행 명령·네이밍 규칙은 대상 프로젝트의 `docs/rules/TESTING.md` 가 단일 출처다.

## 2. 설정 파일

### 위치 — 대상 프로젝트 루트 `harness.config.yml`

`.harness/` 안에 두지 않는다. `work` 가 `.harness/` 를 `.gitignore` 에 자동 등록하기 때문이다. 설정은 팀 정책이므로 커밋되어야 하고, 변경이 PR diff 에 드러나야 한다.

```yaml
# 이 프로젝트가 쓸 테스트 레벨. 쉼표로 구분한다.
test.levels: unit, integration
```

### 형식 — flat key-value 고정

중첩·배열을 쓰지 않는다. `grep` 한 줄로 판정할 수 있어야 하고, YAML 파서를 도입하면 "파싱 실패"라는 개념이 생겨 오판 경로가 열린다. flat key-value 는 파싱이 아니라 **패턴 매칭**이다.

- 콜론 뒤에 **공백 1칸 이상** 필수. `test.levels:unit` 은 **형식 위반**이며 §3-0 이 검출한다.
- 구분자는 쉼표. 앞뒤 공백 허용.
- `#` 이후는 주석.
- 줄 앞 들여쓰기 불가. 판정 패턴이 전부 `^` 앵커라 들여쓰면 설정이 없는 것으로 읽힌다.

> 공백을 필수로 두는 이유는 §3-1 패턴이 값의 앞 경계를 `[[:space:],]` 로 잡기 때문이다. 공백이 없으면 첫 항목이 조용히 누락된다 — 그래서 §3-0 으로 **검출해서 되묻는다.** 검출하지 않으면 `test.levels:unit` 이 "전 레벨 꺼짐"이 되어 테스트가 0건이 되고 아무 신호도 안 남는다.

### 기본값과 `none`

| 파일 상태 | 해석 |
|---|---|
| 파일 없음 | **기본값 `unit, integration`** |
| `test.levels` 키 없음 | **기본값 `unit, integration`** |
| `test.levels:` (값 비어 있음) | **기본값 `unit, integration`** |
| `test.levels: none` | **테스트를 작성하지 않는다** |

**"설정 안 함"과 "테스트 안 씀"은 다르다.** 전자는 기본값으로 떨어지고, 후자는 `none` 을 명시해야 한다. 이 구분이 없으면 "테스트를 안 쓰기로 했다"는 팀의 의사를 적을 칸이 없어진다.

`none` 은 다른 값과 함께 쓸 수 없다. `test.levels: none, unit` 같은 표기는 정의되지 않으며, §3-3 이 검출해 **사람에게 되묻고 진행하지 않는다** (자동 해석하면 어느 쪽으로 틀려도 조용히 틀린다).

## 3. 판정 규칙 — `work` · 스킬 공통

판정 결과는 다음 5종 중 하나다.

| 결과 | 뜻 | 호출자가 할 일 |
|---|---|---|
| `ON` | 그 레벨이 켜져 있다 | 작성한다 |
| `OFF` | 그 레벨이 꺼져 있다 | 작성하지 않고 `<스킬명>: 생략 — <사유>` 기록 |
| `DEFAULT` | 설정이 없다 | 기본값 `unit, integration` 을 적용해 다시 판정 |
| `MALFORMED` | 형식 위반 (§3-0) | **사람에게 되묻고 진행하지 않는다** |
| `CONFLICT` | `none` 혼용 (§3-3) | **사람에게 되묻고 진행하지 않는다** |

### 전처리 — 첫 줄만 취한다

판정 전에 `^test\.levels:` 에 매치하는 **첫 줄 하나만** 뽑는다.

```bash
grep -m1 '^test\.levels:' harness.config.yml
```

`test.levels:` 가 두 줄 이상이면 grep 은 **둘 다 매치**하므로, 전처리 없이는 `unit` 과 `ui` 가 동시에 참이 된다. 전처리 후에는 먼저 나온 줄만 유효하다.
매치가 없으면(파일 없음 / 키 없음) 그대로 `DEFAULT` 다.

이후 **3-0 → 3-1 → 3-2 → 3-3** 을 순서대로 이 한 줄에 적용한다. 3-0 에 걸리면 거기서 멈춘다. **3-3 은 3-1 결과에 의존하므로 반드시 3-1 뒤에 온다** — 순서를 바꾸면 `none, unit` 에서 3-1(`unit`)이 참이 되어 되묻지 않고 그냥 진행한다.

패턴은 전부 **ERE** 다. `grep -E` 로 쓴다.

### 3-0. 형식이 유효한가 (맨 먼저)

```regex
^test\.levels:[^[:space:]]
```

매치하면 **형식 위반**(콜론 뒤 공백 누락)이다. 자동 해석하지 않고 **사람에게 되묻고 진행하지 않는다** (`MALFORMED`).

이 검사가 없으면 `test.levels:unit` 이 3-1 에서 전 레벨 미매치, 3-2 에서 "명시됨"으로 판정되어 **기본값 폴백도 안 되고 되묻지도 않은 채 조용히 `none` 과 같아진다.** "게이트가 열리는 방향으로 틀리면 안 된다"의 정반대 사고이므로 반드시 맨 앞에 둔다.

### 3-1. 특정 레벨이 켜져 있는가

```regex
^test\.levels:[^#]*[[:space:],]<레벨>([[:space:],]|$)
```

`<레벨>` 은 플레이스홀더다. `unit` / `integration` / `ui` / `none` 으로 치환해서 쓴다.

| 조각 | 이유 |
|---|---|
| `[^#]*` | 주석 앞까지만 본다. `test.levels: unit  # no ui` 를 ui 허용으로 오탐하면 **게이트가 열리는 방향**으로 틀린다 |
| 앞뒤 `[[:space:],]` | 부분 일치 차단. `uiflow` 가 `ui` 로 잡히면 안 된다 |

| 설정 줄 | `ui` 판정 |
|---|---|
| `test.levels: unit, integration, ui` | ✅ 켜짐 |
| `test.levels: ui` | ✅ 켜짐 |
| `test.levels: unit, integration` | ❌ 꺼짐 |
| `test.levels: unit  # no ui` | ❌ 꺼짐 |
| `test.levels: uiflow` | ❌ 꺼짐 |

### 3-2. 설정이 존재하는가 (기본값 적용 여부)

3-1 만으로는 **"파일이 없다"와 "명시적으로 뺐다"를 구분할 수 없다.** 둘 다 미매치이기 때문이다. 그래서 판정을 2단으로 나눈다.

```regex
^test\.levels:[[:space:]]*[^[:space:]#]
```

매치하면 "값이 명시됐다" — 3-1 의 결과를 그대로 쓴다.
매치하지 않으면(값이 비었거나 주석뿐) **§2 기본값 `unit, integration` 을 적용한다** (`DEFAULT`).

> 이 2단 구분이 없으면 설정 파일이 없는 프로젝트에서 모든 레벨이 "꺼짐"으로 판정되어 기본값 규정이 무력화된다.

### 3-3. `none` 혼용인가

`none` 은 다른 값과 함께 쓸 수 없다(§2). 검출은 **3-1 을 두 번 적용**해서 한다.

- 3-1 을 `none` 으로 적용한 결과가 참이고,
- 3-1 을 `unit` · `integration` · `ui` 중 하나로 적용한 결과도 참이면

→ **혼용**(`CONFLICT`)이다. 사람에게 되묻고 진행하지 않는다.

값을 split 해서 개수를 세는 방식은 쓰지 않는다 — §2 가 세운 "파싱이 아니라 **패턴 매칭**" 원칙이 깨진다.

## 4. 누가 읽는가

| 주체 | 용도 |
|---|---|
| `work` 1.5 | 이번 작업에 어느 레벨의 테스트를 작성·위임할지 확정. 결과를 run 파일에 1줄 기록 |
| `unit-test` 스킬 | `unit` 이 꺼져 있으면 작성하지 않고 사유를 run 파일에 기록 |
| `integration-test` 스킬 | `integration` 이 꺼져 있으면 작성하지 않고 사유를 run 파일에 기록 |
| `e2e-test` 스킬 | `ui` 가 꺼져 있으면 작성하지 않고 사유를 run 파일에 기록 |

세 스킬의 동작은 **같다** — "작성하지 않고 사유 기록". 레벨별로 다르게 굴지 않는다.

> ⚠️ **기록 주체가 둘로 갈리지 않게 한다.** `work` 경로에서는 `work` 1.5 가 레벨을 먼저 판정하고 **꺼져 있으면 스킬을 아예 호출하지 않는다.** 따라서 위 표의 "스킬이 기록한다"는 **사람이 스킬을 직접 호출한 경우**에 해당한다. 기록 형식은 양쪽 다 `<스킬명>: 생략 — <사유>` 로 고정한다.

**강제는 전부 지시문이다. 이 문서는 hook 을 만들지 않는다.** 이 플러그인의 hook 은 설계 원칙 3(`hooks/block-dangerous-command.sh`)에 따라 안전장치만 담당한다.
