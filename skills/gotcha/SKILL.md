# gotcha — 사람 지식 기록

**코드로 알 수 있는 것을 쓰지 않는다.** 이 스킬은 코드를 읽어 문서를 만드는 스킬이 아니다.

## 트리거

- `/gotcha {내용}` — 사람이 직접 호출. 인자가 없으면 무엇을 기록할지 묻는다.
- `work` 자동 호출 — bug-fix 가 같은 명령에서 2회 이상 돌았을 때, work 종료 직전 1회
- `harness-check` 호출 — triage ①(문서 오류)이고 대상이 `GOTCHA.md`·모듈 `CLAUDE.md` 일 때
- `harness-verify` 호출 — 수정 동의 시

## 절차

1. **한 줄로 만든다.** 형식은 `{내용} — {이유}` 다.
   - **이유를 반드시 받는다.** 이유가 없으면 나중에 이 항목을 지울 판단을 할 수 없다. 없으면 묻는다.
   - 두 줄이 필요하면 두 항목으로 나눈다.

2. **판정한다.** 코드를 읽으면 나오는 내용이면 **기록하지 않고 그 이유를 말한다.**

3. **섹션을 고른다.**

| 섹션 | 담는 것 |
|---|---|
| 과도기 | 같은 역할이 둘일 때 어느 쪽이 목적지인가 |
| 죽은 것 | 코드에 있지만 쓰면 안 되는 것 |
| 하지 마라 | 코드가 허용하지만 팀이 금지한 것 |
| 팀 규칙 | 코드 밖에 있는 규칙 |

위 네 섹션은 `docs/GOTCHA.md` 의 섹션이다. 모듈 `CLAUDE.md` 는 `하지 마라`·`암묵 규칙` 두 섹션만 가진다. 모듈로 보낼 때: `하지 마라`는 그대로 `하지 마라`로, 나머지 셋(과도기·죽은 것·팀 규칙)은 모두 `암묵 규칙`으로 담는다.

4. **배치를 정한다.** 판정 질문은 하나다 — **"이 지식을 알아야 하는 파일들이 한 모듈 안에 있는가?"**

| 조건 | 위치 |
|---|---|
| 한 모듈 안 | `{module}/CLAUDE.md` |
| 여러 모듈 | `docs/GOTCHA.md` |
| 판정 불가 | 3지선다로 사람에게 묻는다 — ① 모듈 ② 전역 ③ 안 넣음 |

**동점이면 모듈이 기본값이다.** 루트 GOTCHA 는 자동 적재라 **항상 읽히고**, 모듈 문서는 조건부라 **그 모듈을 건드릴 때만 읽힌다.**

5. **상한을 본다.** 새 항목을 쓰기 **전에** `node ${CLAUDE_PLUGIN_ROOT}/shared/scripts/verify-docs.mjs {레포루트}` 를 실행한다. 이 명령은 상한이 있는 문서마다 `COUNT {파일}: {현재줄수}/{상한}줄` 줄을 출력한다 — 대상 문서(`docs/GOTCHA.md` 또는 해당 `{module}/CLAUDE.md`) 줄에서 현재 줄 수를 읽어 다음을 판단한다.

| 상태 | 처리 |
|---|---|
| `docs/GOTCHA.md` 50줄 초과 | 모듈로 내릴 항목 후보를 제안한다. 추가는 진행한다 |
| **60줄 도달** | 새 항목을 넣기 전에 **기존 항목 하나를 모듈로 내리거나 지운다.** 사람이 고른다. **자동 삭제하지 않는다** |

6. **쓴다.**
   - `docs/GOTCHA.md` 가 없으면 `@${CLAUDE_PLUGIN_ROOT}/shared/templates/gotcha.md` 골격으로 만든다.
   - 모듈 파일이 없으면 `@${CLAUDE_PLUGIN_ROOT}/shared/templates/module-claude.md` 골격으로 **그때 만든다.** 미리 만들지 않는다.
   - 해당 섹션이 없으면 섹션 헤더와 함께 추가한다. 빈 섹션 헤더를 미리 만들지 않는다.

7. **보고한다.** 기록한 파일 경로와 추가한 줄을 보여준다.

## 하지 않는 것

- 코드를 읽어 문서를 생성하지 않는다.
- 사람이 답하지 않은 내용을 추측으로 채우지 않는다.
- 이유 없는 항목을 기록하지 않는다.
- 상한 초과 시 기존 항목을 자동으로 지우지 않는다.
