# e2e-test — 사용자 플로우 E2E 테스트 작성 (test-after, 사람 게이트)

이번 work 가 **완성시킨 사용자 플로우**의 E2E 테스트 *코드를 작성*한다. 기기/시뮬레이터가 필요하므로 **자동 실행하지 않고** 사람 게이트로 넘긴다.

## 강제 법칙

> **완성된 플로우만, 사용자 관점으로 짠다. 자동 실행하지 않는다 — 사람 게이트.**

E2E 는 사용자 여정 단위라 단일 work 와 1:1 이 아니다. 플로우가 닫힌 work 에서만 작성한다.

## 언제

- `work` 6.5 에서 이번 work 가 **사용자 플로우를 완성시켰다**고 판단해 호출할 때만.
- 플로우 미완성이면 호출되지 않는다(work 가 "e2e-test: 생략 — 사유"로 기록).

## 책임 경계

| 한다 | 안 한다 |
|---|---|
| `test-writer` 에 **작성 위임** + 실행 명령 준비 | 테스트 **자동 실행** (기기 필요 → 사람 게이트) |
| run 파일에 "수동 실행 대기" + 단언 요약 + 명령 기록 | **무엇을 단언할지 도출** (→ `work` 6.5-B) / 모듈 경계 통합 테스트 (→ `integration-test`) |
| 레벨 확인 · 그린필드 가드(규칙 비면 분기) | 필요 여부 **판단** (→ `work` 6.5) |

## 절차

1. **레벨 확인**: 대상 프로젝트 루트 `harness.config.yml` 에 `shared/test-levels.md` §3 판정을 적용한다.
   - `ui` 가 꺼져 있으면 **작성하지 않고** `.harness/runs/run-{id}.md` 에 `e2e-test: 생략 — ui 레벨 꺼짐` 을 기록하고 끝낸다.
   - `MALFORMED` / `CONFLICT` → 사람에게 되묻고 진행하지 않는다.
   - `work` 경로에서는 6.5-B 가 이미 걸러 호출하지 않는다. 이 확인은 **사람이 이 스킬을 직접 호출한 경우**를 위한 것이다.

2. **도구 로드**: `@docs/rules/TESTING.md` 에서 E2E 도구/명령(예: Android Espresso/Maestro, iOS XCUITest/Maestro)을 읽는다(단일 출처).
   - ⚠️ **그린필드 가드**: E2E 도구·규칙이 비어 있으면 → 작성을 멈추고 `/harness-root`(또는 `/harness-root-edit testing`) 로 분기해 스택을 먼저 확정한다.

3. **작성 위임**: `work` 6.5-B 가 도출한 3열 명세(파일 / 레벨 / 단언할 것)의 `ui` 행을 **`test-writer` 에이전트**에 전달하고, 실행 명령을 준비한다.
   - 함께 전달: 허용 레벨(1.5 확정값) · run-id · `docs/rules/TESTING.md` 경로 · 아래 제약.
   - **무엇을 단언할지는 이 스킬이 정하지 않는다** — `work` 6.5-B 가 도출한다. 이 스킬은 명세를 그대로 넘기는 통로다.
   - 함께 넘기는 제약: **사용자가 실제로 보고 도달하는 상태**를 단언한다. "화면이 떴다"는 단언이 아니다.
   - ⚠️ **재작성 모드 (pass-through)**: `test-reviewer` 위반 목록을 함께 받았으면(6.7 `fix-tests`) **원 명세와 위반 목록을 둘 다 그대로** `test-writer` 에 넘긴다. **요약·가공하지 않는다.** 위반 목록을 빠뜨리면 같은 입력 → 같은 출력이 되어 재시도가 2회를 헛돌고 사람에게 넘어가는 것이 기본 경로가 된다.

4. **자동 실행 금지**: 돌리지 않는다. `.harness/runs/run-{id}.md` 의 **E2E 수동 실행 대기 목록**에 `test-writer` 가 보고한 작성 파일 + 단언 요약 + 실행 명령을 기록하고 사람 게이트로 넘긴다.

## 시나리오 예시 (무엇이 "사용자 관점 단언"인가)

로그인 플로우를 완성시킨 work 를 예로 든다. 핵심은 사용자가 *실제로 보고 도달하는 상태*를 단언하는 것이다.

**약한 단언:**
```
// 화면이 떴는지만 본다 — 사용자가 로그인에 성공했는지는 모른다
onView(withId(R.id.login_screen)).check(matches(isDisplayed()))
```

**사용자 관점 단언:**
```
// 사용자 여정대로: 입력 → 제출 → 도달한 결과 화면을 단언
onView(withId(R.id.email)).perform(typeText("a@b.com"))
onView(withId(R.id.password)).perform(typeText("pw1234"))
onView(withId(R.id.submit)).perform(click())

// 사용자가 로그인 성공으로 "도달하는" 홈 화면의 환영 문구를 단언
onView(withText("환영합니다, a@b.com")).check(matches(isDisplayed()))
```

## 가드

- 미완성 플로우에 E2E 를 짜지 않는다(work 6.5 가 완성 판단 후에만 호출하지만, 스킬 안에서도 재확인한다).
- "화면이 떴다"가 아니라 사용자 관점의 결과 상태를 단언한다.

## 원칙

- 스킬=통로, 작성은 `test-writer`. 실행은 기기 위에서 사람이 트리거한다(자동 루프 비편입).
- 규칙은 `TESTING.md` 단일 출처. 도구/명령을 여기 하드코딩하지 않는다.
