# test-level — 테스트 범위 확인·변경

이 프로젝트가 **어느 레벨의 테스트를 작성할지**를 보여주고 바꾼다. 대상 파일은 프로젝트 루트 `harness.config.yml` 하나다.

레벨 정의와 판정 규칙은 `shared/test-levels.md` 가 단일 출처다. 이 스킬은 그것을 **참조**하며 규칙을 여기 다시 적지 않는다.

## 트리거
- `/test-level` — 현재 설정 표시 후 선택

## 책임 경계

| 한다 | 안 한다 |
|---|---|
| 현재 레벨 표시 | 테스트 코드 작성 (→ `unit-test` / `integration-test` / `e2e-test`) |
| 레벨 선택·파일 쓰기 | 테스트 실행 (→ `completion-verifier`) |
| 파일이 없으면 생성 | `work` 호출 |
| 형식 위반·`none` 혼용 교정 | 레벨 **정의** 추가·변경 (→ `shared/test-levels.md` §1) |

## 흐름

### 1. 판정
대상 프로젝트 루트 `harness.config.yml` 에 `shared/test-levels.md` §3 판정(전처리 → 3-0 → 3-1 → 3-2 → 3-3)을 적용한다.

### 2. 현재 상태 표시
레벨별 상태와 출처를 표로 보여준다. 출처는 `파일` / `기본값` / `파일 없음` / `형식 위반` / `none 혼용` 중 하나다.

```
현재 테스트 범위 (harness.config.yml)
| 레벨          | 상태 | 담당 스킬          |
|---------------|------|--------------------|
| unit          | ON   | unit-test          |
| integration   | ON   | integration-test   |
| ui            | OFF  | e2e-test           |
출처: 기본값 (파일 없음)
```

`MALFORMED` · `CONFLICT` 일 때는 상태 대신 **문제가 된 줄 그대로**를 보여주고 다음 단계로 진행한다. **다른 호출자는 여기서 멈추지만 이 스킬은 멈추지 않는다** — 그 상태를 고치는 것이 이 스킬의 목적이다.

### 3. 선택
`unit` / `integration` / `ui` / `none` 을 **다중 선택**받는다. 현재 켜진 레벨을 기본 선택 상태로 둔다.

### 4. `none` 혼용 거부
`none` 이 다른 값과 함께 선택되면 **파일에 쓰지 않고** 그 자리에서 되돌려 재선택시킨다.

> `none` 은 "테스트를 안 쓰기로 정했다"는 의사 표시다. 다른 값과 같이 쓰면 뜻이 정의되지 않는다. `CONFLICT` 를 파일에 써 넣으면 이후 모든 `work` 가 멈춘다 — 그래서 쓰기 **전에** 막는다.

### 5. 쓰기

| 파일 상태 | 동작 |
|---|---|
| 파일 없음 | `shared/test-levels.md` **§2 생성 템플릿** 을 그대로 쓰고 `test.levels` 값만 선택값으로 바꾼다 |
| `^test\.levels:` 매치 줄 있음 | **첫 매치 줄만** 교체한다. 둘째 줄 이후·다른 줄은 건드리지 않는다 |
| 파일 있음 · 매치 줄 없음 | 파일 끝에 `test.levels: <선택값>` 한 줄을 덧붙인다 |

형식 위반 줄(`test.levels:unit`)도 매치 줄이므로 교체 대상이다. 이 교체가 4단계 다음으로 중요한 이 스킬의 존재 이유다.

값은 항상 `콜론 + 공백 1칸 + 쉼표와 공백으로 구분된 값` 으로 쓴다. 예: `test.levels: unit, integration, ui`

### 6. 결과 요약

```
✅ test-level: harness.config.yml 갱신
- 이전: unit, integration
- 이후: unit, integration, ui
- 파일: <절대경로> (생성됨 / 갱신됨)
```

## 원칙
- 이 파일은 **커밋되는 팀 정책 파일**이다. 바꾼 내용을 항상 사람에게 보여준다.
- 판정 규칙을 복사하지 않는다. 두 곳에 적으면 갈라진다.
- `.harness/` 안에 만들지 않는다 — `work` 가 `.harness/` 를 `.gitignore` 에 등록하므로 설정이 커밋되지 않는다.
